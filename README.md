Q. Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?

This app was designed to address the need to keep track of inventory in a warehouse. 

The requirements for the app I developed are:  
- A database with at least two tables, one to store the inventory items and one to store user logins and passwords
- A screen for logging into the app / sign up a new account
- A screen with a grid that displays all items in the inventory
- A mechanism by which the user can add and remove items from the inventory
- A mechanism by which the user can increase or decrease the number of a specific item in the inventory
- A mechanism by which the application will notify the user when the amount of any item in the inventory has been reduced to zero

Q. What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?

I included a few screens in order to support user needs and produce a user-centered UI for the app. These screens are: the login screen, the inventory grid screen, the add inventory item screen, and the sms notifications permissions screen. I kept the design simplistic and straightforward since this is a warehouse inventory app and function and ease-of-use matters more than aesthetics. The screens I chose are ones that are absolutely necessary for user needs to avoid bloating the application with superfluous screens. By utilizing a grid, the inventory items are easy to view and navigate. 

Q. How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?

I approached the process of coding this app by using the Software Development Lifecycle (SDLC) framework to break down the process into smaller parts, which was simulated by the course's project milestones. By leaning on Agile techniques, I was able to create the different functions of the application without being overwhelmed or overcommitting on features that were not necessarily part of the users' needs. I began using these strategies after previous courses and I have found success with them, so I will continue to apply these techniques to build up this inventory app further. 

Q. How did you test to ensure your code was functional? Why is this process important, and what did it reveal?

I test throughout the development process by breaking up the overall application into smaller tasks that I would like the application to perform. As I develop each task, I test that task to ensure that the code is doing what I intended it to do. This process of incremental testing is important because it allows me to see bugs or other potential issues as they appear earlier on in the development process. Plus, it gives me a baseline of how a method functions on its own, which helps with debugging later on when different classes are interacting with each other. 

Q. Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?

A challenge I ran into is the SMS notification component. Since I was testing my application on an emulator, I could not accurately assess the SMS notification function because the emulator isn't attached to a phone number. In order to get an idea of whether the SMS system was working or not, I added a toast message so that I could test whether the SMS notification activity successfully "sent" an out-of-stock SMS alert.
